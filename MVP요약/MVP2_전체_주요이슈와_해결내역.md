# MVP2 전체 — 주요 문제점·해결 내역·남은 한계

정리일: 2026-10-21 · 현재 코드 기준: v0.5.24

이 문서는 최근 v0.5.23~v0.5.24 수정 두 건의 요약이 아니다. **MVP2/M2 개발 과정 전체에서 발생한 큰 문제와 현재 남은 문제를 통합한 기록**이다. 초창기 2D·MediaPipe 기반 경로, SAM3D 도입, 사람 추적 분리, SAM 2 전환, 후보 비교와 부위 재추정 과정까지 포함한다.

과거에 발생했던 문제를 현재도 그대로 발생하는 확정 오류로 표시하지 않는다. 반대로 특정 영상에서 좋아졌다는 이유로 모든 입력에서 해결됐다고 표시하지도 않는다. 누적 이슈 원본은 [ISSUES.md](../md/ISSUES.md), 개발 내역은 [PROGRESS.md](../md/PROGRESS.md)다.

## 2. 대상 추적에서 겪은 문제

### 2.1. 다른 사람이나 거울 속 인물로 대상이 바뀜

**증상:** 같은 인물을 따라가다가 다른 후보에 연결되거나, 작은 반사 인물에 추적이 붙었다.

**확인한 취약점:** 초기의 검출 박스·관절 기반 연결은 회전이나 가림에서 후보의 외형·박스·관절이 달라지면 흔들렸다. 관절 오추정이 사람 연결 판단에도 영향을 줬다. 최초 프레임 고정 ROI는 역동적인 인물이 영역을 벗어나는 문제도 있었다.

**대응:** 초기 대상 선택, 매 프레임 ROI 갱신, 복합 연결 점수, 위치·속도 예측, 짧은 재연결 확인, 장기 분실 보호를 단계적으로 비교했다. 이후 기본 경로는 **SAM 2로 사람 마스크 추적 → 그 ROI에서 SAM3D 자세 추정**으로 분리했다. 초기 대상 선택에 쓰는 검출과 추적 이후 자세 추론의 역할을 구분했다.

**현재 한계:** SAM 2의 객체 메모리가 유지돼도 실제 동일 인물임을 증명하는 것은 아니다. 거울·교차·큰 가림·장면 전환의 모호성은 남는다. 예전 복합 점수의 모든 요소가 현재 SAM 2 경로에서 매 프레임 동시에 실행되는 것으로 설명하지 않는다.

### 2.2. 한 사람의 다중·중첩 후보 때문에 멈춤

**증상:** 같은 사람의 부분 박스나 중첩 자세가 여러 후보로 검출되어 다중 인물 또는 대상 불확실로 처리됐다. Norma 초반에 동일 인물의 nested 중복이 초기화를 막는 경우가 있었다.

**대응:** 박스 겹침만 보지 않고 크기·높이·포함 관계·외형·관절 근거에 따른 중복 통합을 보강했다. 실제 다른 사람이 교차하는 경우를 단순히 겹쳤다는 이유로 합치지 않도록 보호했다.

**현재 한계:** 특정 중복 사례는 해결했으나 모든 검출 중복을 해결한 것은 아니다. 후보를 무조건 하나로 줄이면 다른 사람까지 합치는 반대 오류가 생긴다. 현재 기본 SAM 2 모드에서도 초기 후보가 여러 명이면 사용자의 번호 선택이 필요하다.

### 2.3. 회전·뒤돌기·웅크림·빠른 동작에서 끊김

**증상:** 상체를 숙이거나 뒤돌 때 박스가 줄고 관절이 없어지며, 추적이 끊기거나 위치가 튀었다. Norma, Vivian, Sword, 뒤차기 영상 등에서 반복 확인했다.

**대응:** 몸 중심·박스 기반 움직임 예측과 Kalman, 위치 잔차 검사, 재검출·재연결 보호, SAM 2 마스크 추적, 보수적인 ROI 변화를 단계적으로 적용했다. 현재 기본 마스크 움직임 검사의 관측은 **가시 마스크의 중심**이며, 실제 척추·골반·root를 직접 측정한 것이 아니다.

**실패한 방향:** 몸통 조건을 너무 엄격하게 걸면 정상 회전까지 거부돼 이전보다 추적이 줄었다. 임계값을 완화하면 모호한 다른 후보를 허용하는 회귀도 있었다. 모든 영상에 동일한 조건 강화·완화를 적용하는 것으로 해결하지 않았다.

**현재 한계:** 일반 영상은 사용자 확인에서 개선됐다. 긴 분실·강한 가림·장면 전환 뒤에는 같은 대상과 자세를 확정할 근거가 부족할 수 있다. 예측된 위치를 실제 관측 ROI로 삼아 계속 추론하지 않는다.

## 3. 자세·관절 추정에서 남은 큰 문제

### 3.1. 옷·망토·머리카락·장식품을 팔이나 다리로 추정

**MVP2의 가장 큰 잔여 문제다.** 사람은 잘 따라가더라도 같은 사람 안에서 팔·다리 위치가 잘못 추정된다. 특히 Norma 회전 구간에서는 망토에 다리 관절이 붙는다.

이 오류는 관절이 아예 없는 결측과 다르다. 잘못된 위치에도 유한한 좌표와 그럴듯한 본 길이가 출력되므로, 단순 누락 보간이나 흔들림 제거가 작동하지 않을 수 있다. 사람 전체 마스크 안에 있다는 조건도 의류와 실제 신체를 구분하지 못한다.

적용한 관절별 속도·시간 잔차·길이·좌우 연결·마스크·화면 경계 검사는 일부 이상을 잡지만, 모델 후보들이 같은 위치에 함께 틀리는 경우를 모두 판별하지는 못한다.

**현재 결정:** 일반 영상의 개선 상태를 기준으로 다음 단계 준비를 하고, 펄럭이는 의상으로 심하게 가려지는 Norma는 알려진 한계로 보류한다. 해결된 영상으로 바꾸거나 회귀 자료에서 제거하지 않는다.

### 3.2. 골반·몸통 기준 자체가 잘못됨

팔다리 재추정은 몸통과 연결점을 기준으로 한다. 그 기준이 이미 망토 쪽으로 틀어져 있으면 다음 문제가 생긴다.

- 실제 다리처럼 보이는 후보가 기존 골반·본 길이 제약과 충돌해 거부된다.
- 팔다리만 수정하면 연결점에서 꺾이거나 길이가 달라진다.
- 잘못된 몸통을 고정한 상태에서는 다리 후보를 더 많이 만들어도 한계가 있다.

전신 후보와 골반·어깨 중심, 몸통 기준축을 후속 단계에 전달하도록 보강했다. 다만 이 기준축도 모델 관절에서 계산한 파생값이지 실제 척추 본의 정답 측정값은 아니다. 몸통까지 함께 잘못된 구간은 여전히 별도 문제다.

### 3.3. 좌우·앞뒤·가려진 관절 방향의 모호성

회전·교차·옷 가림에서는 좌우 다리나 무릎 굽힘 방향을 잘못 선택할 수 있다. 수동 지정에서는 화면 왼쪽과 인물의 해부학적 왼쪽을 혼동하는 문제도 있었다.

좌우 연결 검사, 반전 입력 후보 복원, 시간 경로 비교, 길이·투영 제약을 추가했다. 하지만 단일 영상에서 보이지 않는 무릎 깊이와 정확한 앞뒤 자세를 모든 경우에 결정할 수 있게 된 것은 아니다. 매끄러운 3D 가설도 잘못된 방향일 수 있다.

### 3.4. 대기 자세 떨림·관절 점프·보정 종료 경계의 튐

초기부터 정지·대기 동작의 작은 떨림이 있었고, 빠른 동작이나 후보 전환에서는 큰 점프도 발생했다. 일부 프레임만 보정하면 수정 구간에 들어가거나 나오는 경계에서 다시 튀었다.

관절별 검사, 연속 구간 후보 선택과 재관측 연결을 보강했다. 원시 관측으로 돌아올 때도 연속 관측과 길이·이동 조건을 확인하고, 실패하면 강제로 연결하지 않도록 했다.

최종 애니메이션의 본 회전·접지까지 포함한 시간 보정은 아직 후속 범위다. Euler 평활 대신 Quaternion·부호 연속성·SLERP를 사용할 계획과 현재 구현된 관절 위치 검사를 구분한다. 강한 평활은 빠른 실제 동작을 둔화시킬 수 있어 만능 해결책으로 쓰지 않는다.

### 3.5. 영상 밖 손발과 긴 가림을 복원할 근거 부족

Sword처럼 발이 화면 밖으로 잘리는 경우에는 실제 발 위치를 영상에서 관측할 수 없다. 짧은 누락, 부모 관절 상대 보간, 길이 보존과 명시적 다리 가설 등을 적용했고 사용자가 발 보완 개선을 확인했다.

그러나 다음은 남는다.

- 긴 가림의 실제 궤적, 발 방향과 정확한 좌우 구분
- 양끝 기준 자세가 모두 틀렸거나 서로 다른 장면·추적 구간인 경우
- 부모만 보완할 때 자식 관절 길이가 달라지는 문제와 이를 막는 연결 제약
- 처음부터 발이 잘린 경우에 초기 신발 근거를 만들기 어려운 구형 다리 재추정 경로

짧은 보완·IK 가설과 관측을 분리한다. 장기 분실이나 장면·대상 경계를 넘어 임의로 이어 붙이지 않는다. 부모 보완 후 길이 붕괴는 길이 보존 보강을 했지만 숨은 실제 동작의 정답을 확보한 것은 아니다.

## 4. 시도했지만 근본 해결이 되지 않은 접근

### 4.1. 수동 관절·무릎 앵커

사용자가 관절을 지정해도 이후 프레임에서 모델의 잘못된 관절로 돌아가거나 더 튀는 현상이 있었다. 저장·불러오기·현재 프레임·좌표계·반영 경로와 별개로, 한 프레임의 지정만으로 회전 뒤의 가려진 신체를 계속 추적하기 어렵다는 한계도 있었다.

앵커 관련 경로를 점검하고 비교했지만 사용자 체감 개선이 충분하지 않았다. 이후 요청에 따라 관절/무릎 지정과 사용하지 않는 시험 UI를 기본 화면에서 제거하고 자동 후보·관절 검사·부위 재추정으로 전환했다.

**현재 상태는 ‘수동 앵커로 의상 오류 해결’이 아니라 ‘문제가 있던 기본 사용 흐름을 대체’한 것이다.** 과거 결과와 공유 엔진은 보존했다.

### 4.2. 발목이나 신발이 맞으면 다리 전체가 맞다고 보는 사각지대

구형 다리 재추정에서는 발목이 신발 마스크 안에 있으면 교체 필요성이 낮다고 판단해, 무릎·골반 오류를 놓칠 수 있었다. 신발 마스크도 모델의 초기 발 추정에서 만들어진 경우가 있어 처음부터 의상을 쫓을 위험이 있었다. 교차 시 같은 신발을 중복 추적하는 문제도 관찰됐다.

이후 발목 일치만 보지 않고 무릎·골반·팔까지 관절별로 검사하고 필요한 부위만 재추정하는 현재 흐름으로 발전시켰다. 신발 마스크 일치도나 후보 교체 횟수는 다리 전체 정확도의 지표로 사용하지 않는다.

### 4.3. 후보를 늘려도 모두 같이 틀림

원시·ROI 변형·반전 입력 등 여러 전신 후보를 만들면 선택지는 늘지만 독립적인 정답 관측이 추가되는 것은 아니다. 후보가 공통으로 옷에 붙거나 잘못된 골반을 유지하면 가장 낮은 비용의 후보도 틀릴 수 있다.

부위 재추정도 본 길이·몸통·투영·마스크 제약에 맞는 후보가 없으면 기존 결과를 유지한다. 따라서 ‘재추정 완료’와 ‘실제로 수정됨’, ‘실제 정답으로 개선됨’은 서로 다른 상태다.

### 4.4. 의상 마스크·시간 보간·다른 모델 비교의 한계

| 시도 | 확인한 한계 |
|---|---|
| 사람 안 망토·머리카락 별도 마스크 | 작업자 seed의 비교용 영역. 의상과 실제 가려진 관절이 겹쳐 있어 삭제만으로 정답이 나오지 않음 |
| 사람/의상 겹침으로 후보 감점 | 일부 후보 선택은 달라져도 심한 다리 오류는 남음 |
| SAM3D에 직접 마스크 조건 입력 | 출력 변화는 확인했지만 핵심 의상 오류 해결은 확정하지 못함 |
| 앞뒤 프레임 자세 가설·보간 | 긴 구간과 잘못된 양끝 자세에서는 실제 중간 동작을 복원할 근거 부족 |
| 독립 RTMPose → MotionBERT | 독립 2D도 옷에 붙는 구간이 있어 시간 모델만으로 정답을 확보하지 못함 |
| 검사 통과 2D 관절의 SAM3D point prompt | 입력 관측이 유효한 부위에만 사용 가능. 핵심 2초대 다리에는 통과 관측 부족 |

일부 실험은 제한된 표본 비교다. 여러 실험의 프레임 수나 정합 통과 수를 합산해 전체 영상 정확도 개선율로 쓰지 않는다. 이 실험들이 전부 기본 자동 추출에 적용된 것도 아니다.

## 5. 품질 판정과 데이터 해석의 문제

### 5.1. 점수·연속성·완료 상태가 정확도처럼 보임

높은 모델 점수, 마스크 유지, 본 길이 일치, 매끄러운 움직임이나 성공적인 파일 저장은 실제 관절 정답을 보장하지 않는다. 후보가 함께 틀리거나 매끄럽게 의상을 따라가는 경우가 있다.

원시·모델 관측·예측·보간·재추정·재연결의 출처와 검사 사유, 미해결 상태를 분리해 저장하도록 보강했다. 비교 영상과 원시 결과를 유지한다. 현재 정량 검사는 파일 정합·제약 통과·연속성 검토가 중심이며, 전체 입력에 대한 정답 관절 데이터 기반 정확도 검증은 확보하지 않았다.

### 5.2. 관절 위치 보정과 본 회전·게임 애니메이션의 차이

현재 보정 결과는 주로 별도 관절 데이터다. 원시 SAM3D의 native 회전 파라미터가 보정 관절과 함께 재계산된 것은 아니다. 카메라 상대 좌표를 Unreal 월드 좌표, Root Motion이나 접지 해법으로 볼 수도 없다.

이는 다음 단계의 기능 경계이며, 이미 구현된 기능의 오류로 섞지 않는다. **M3 표준 스켈레톤 변환, M4 본 회전, 이후 접지·Root·리타게팅·편집**을 실제로 구현·검증해야 게임 에셋으로 이어진다. 위치 보정 미리보기가 좋아졌다는 이유로 이 과정을 완료 처리하지 않는다.

## 6. 성능·입력·실행 환경의 큰 문제

### 6.1. GPU 추출 시간이 많이 걸림

한 프레임의 원시 SAM3D 추론 외에 추가 전신 후보 3개와 필요한 부위 재추정까지 실행한다. 당시 LongSword 445프레임에는 총 2,082회가 요청됐다. 이는 실제 완료한 전체 추론 횟수가 아니라 요청 작업량이며 부위 처리 도중 배치를 중단했다.

또한 GUI 추출과 일괄 추출이 동시에 실행되는 것을 확인했다. RTX 4060 8GB에서 사용률 100%, 전용 메모리 약 7.5/8GB였고 열 제한은 감지되지 않았다. 사용자 요청으로 일괄 프로세스만 종료하고 GUI와 기존 결과를 보존했다.

**남은 일:** 단독 동일영상·버전별 속도 비교, 최대 길이의 GPU/CPU 메모리 측정, 필요한 구간에만 후보를 늘리는 최적화 검토. 메모리 paging이나 버전 자체의 일률적인 속도 회귀를 측정 없이 확정하지 않는다.

### 6.2. 긴 영상과 시작 부분 인물 부재

이 두 문제도 MVP2 전체 이슈 중 일부다.

- **긴 영상:** 기존 60초/3,600프레임 제한을 5분/18,000프레임으로 공통화했다. 최대 1,920px 짝수 해상도와 2GiB 제한은 남아 있다. 긴 SAM 2의 오래된 기억 저장도 제한했다. 실제 최대 길이의 GPU 부하·후속 대형 JSON 메모리는 별도 검증이 남는다.
- **나중 등장:** 첫 검출 프레임 탐색과 사용자가 고른 프레임의 seed 시작을 연결했다. 등장 전 프레임은 빈 상태로 보존한다. 2026-10-21 사용자 정상 동작 확인을 받았다.

자세한 최근 변경은 [v0.5.24 이슈해결 요약](v0.5.24_MVP_이슈해결_요약.md)에 별도 보존한다.

### 6.3. 모델·런타임·파일 경로 문제

초기에는 모델 사용 조건 검토에 따른 선정 변경, 모델별 접근 승인, 다운로드 공간 부족과 GPU 환경 준비 때문에 진행이 막혔다. 모델 승인·가중치 확보·별도 CUDA 환경 설치 후 실제 추론을 연결했다. 당시 결정과 자산 검증 기록을 보존한다.

한국어 경로에서 MediaPipe 및 TorchScript 모델 로딩이 실패한 사례는 검증된 바이트 버퍼 등 경로별 대응으로 해결했다. OpenCV 배포판 중복 위험은 환경 정리로 대응했다. NumPy 후보 배열을 단순 bool로 검사하던 오류도 수정했다.

후속 native point prompt 실험에서는 upstream API의 지원되지 않는 `full_output=None` 인자로 실패했다. 비교 어댑터에서 해당 호환 문제만 처리했고 관련 없는 오류까지 숨기지 않았다. 기본 모델 교체나 원본 가중치 수정으로 해결한 것은 아니다.

### 6.4. 취소·부분 실패·기존 결과 보존

Windows venv 실행기만 종료하고 실제 추론 자식이 남을 수 있는 문제가 있었다. 본인이 시작한 자식 트리만 중지하는 경로를 보강했고, 권한 있는 환경의 실제 자식 종료 확인 이력도 남겼다. 해당 권한 opt-in 시험을 일반 실행에서 건너뛴 사실과 구분한다.

자동 후처리가 일부 실패해도 완료된 원시·후보 결과를 보존하고 단계별 상태를 기록한다. 취소·실패·부분 완료를 정상 완료로 표시하지 않는다. 프로세스 중지로 남은 부분 결과도 사용자의 파일을 임의로 삭제하지 않고 상태를 남긴다.

### 6.5. 사용성과 검증 환경

- 명령어를 매번 입력하던 불편은 드래그 앤 드롭·출력·미리보기의 데스크톱 프로그램으로 개선했다.
- 이전 결과를 찾기 어려운 문제는 상시 결과 패널, 하위 비교 영상 선택, 삭제·프로그램 휴지통·복원으로 대응했다.
- 밝은 목록 배경의 가독성은 어두운 색상으로 통일했다.
- 여러 Tk 생성 또는 결합 검증 중 초기화 실패, pytest 통과 요약 뒤 Windows 비정상 종료가 간헐적으로 관찰됐다. GUI 시험을 분리해 통과 여부를 확인했지만 근본 원인을 고쳤다고 선언하지 않았다(QA-002/GUI-001 계열).

## 7. 다음 단계 전에 가져갈 결론

### 계속 보존할 미해결 문제

1. 의상·머리카락을 신체로 추정하는 오류, 특히 Norma의 심한 가림.
2. 잘못된 골반·몸통을 기준으로 하는 재추정의 한계.
3. 긴 가림·화면 밖 관절의 실제 위치·좌우·깊이·방향 불확실성.
4. 떨림과 보정 전환 경계의 튐, 빠른 실제 동작을 보존하는 시간 보정.
5. 마스크·후보·모델이 함께 틀릴 때의 오류 판별 부족.
6. 대상 장기 분실·장면 전환 뒤의 신원 모호성.
7. 다중 추론 비용과 실제 최대 영상 길이의 성능·메모리 검증.
8. 전체 정답 관절에 대한 정량 정확도 검증과 간헐 시험 환경 오류.

### 다음 단계 진행 기준

사용자가 일반 영상에서 확인한 개선된 경로를 현재 MVP2 기준으로 유지하고 M3 Motion Skeleton 준비로 넘어간다. Norma의 심한 의상 가림은 별도 보류·회귀 사례로 남긴다. 다음 단계 구현은 이 문서 작성에서 시작하지 않았다.

후속 변환에서는 관측·추정·미해결과 장면/대상 경계를 유지한다. 잘못 추정된 관절을 스켈레톤 매핑이나 Quaternion 변환만으로 고칠 수 있다고 가정하지 않는다. 현재 기록의 M2 상태를 모든 문제 해결·전체 정확도 PASS로 바꾸지 않는다.
