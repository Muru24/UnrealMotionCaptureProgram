# v0.5.24 MVP — 이슈 해결 및 다음 단계 인계

- 정리일: 2026-10-21
- 기준 버전: v0.5.24 (v0.5.23의 긴 영상 지원 포함)
- 범위: 현재 기본 SAM 3D + SAM 2 마스크 모드와 이 버전에 도달하기까지의 주요 보완 사항
- 사용자 확인: 2026-10-21, 늦은 인물 등장 지원 적용 후 “잘 된다” 확인
- 이번 작업: 문서 정리만 수행. 프로그램 코드·모델·기존 MVP ZIP은 변경하지 않음

## 1. 현재 MVP에서 가능한 작업

로컬 MP4를 넣고 대상을 선택하면 사람 추적과 전신 자세 추정을 수행하고, 자동 검사·재추정 결과를 미리보기로 확인할 수 있다.

```text
MP4 입력·정보 검사
→ 최초 인물 탐색 또는 사용자가 지정한 프레임에서 후보 확인
→ 선택 대상의 SAM 2 마스크 추적
→ 유효한 대상 ROI에 SAM3D 전신 추론
→ 원시 결과를 포함한 전신 자세 후보 비교·선택
→ 골반·어깨 등 몸통 기준과 관절별 움직임·길이·영상 근거 검사
→ 필요한 팔·다리만 문맥 영역에서 재추정
→ 재관측 검사·연결
→ 원시/단계별 결과와 비교 미리보기 저장
```

기존 결과를 덮어쓰지 않고 새 결과 폴더에 저장한다. 프로그램의 미리보기 옆 결과 패널에서 저장 결과를 찾아 재생하거나 삭제할 수 있다. 수동 무릎 앵커·관절 지정 UI는 현재 기본 작업 흐름에서 사용하지 않는다.

현재 결과는 카메라 상대 MHR70 관절 추정과 단계별 보정 데이터다. Unreal 월드 좌표의 완성된 애니메이션, 최종 리타게팅, 본 회전 생성까지 완료된 상태는 아니다. 보정된 관절 좌표가 원래 모델의 본 회전에 자동 반영된 것으로 해석하지 않는다.

## 2. 이번에 해결한 입력 문제

### 2.1. 약 3분 영상을 넣으면 처리되지 않음

**확인된 원인**

사람 인식 실패가 아니라 입력 길이 제한이었다. GUI가 60초 또는 3,600프레임 초과를 거부했고, 실제 추출 worker와 일부 후처리에도 별도의 프레임 제한이 남아 있었다.

**해결 방법 — v0.5.23**

- 사용자 요청에 따라 최대 5분(300초), 총 18,000프레임으로 확장했다.
- GUI, 2D, MediaPipe 3D, SAM 2, SAM3D, 관절 완성 후처리의 관련 제한을 함께 맞췄다.
- 길이·프레임 정책을 `core/video/limits.py`에서 공유하도록 했다.
- 긴 SAM 2 단방향 처리에서는 미래 추론에 필요하지 않은 오래된 비조건부 추적 출력을 제거한다. 필요한 최근 기억과 최초/조건부 대상 정보는 유지한다.
- 기존 짧은 영상의 SAM 2 처리 경로는 유지했다.

**현재 입력 규격**

| 항목 | 한도 |
|---|---|
| 형식 | 로컬 MP4 |
| 길이 | 최대 300초 |
| 총 프레임 | 최대 18,000 |
| 해상도 | 가로·세로 각각 최대 1,920px, 짝수 크기 |
| 파일 크기 | 최대 2GiB |

길이와 프레임 제한을 모두 만족해야 한다. 5분·60fps는 한도에 들어가지만, 더 높은 fps 영상은 5분 이내라도 프레임 수 때문에 거부될 수 있다. 자동으로 fps나 해상도를 낮추지는 않는다.

**검증과 남은 범위**

실제 합성 MP4 300초·60fps·18,000프레임의 입력, CPU 대역을 이용한 추출, 출력 전체 디코딩과 시간 정합을 확인했다. 긴 추적의 기억 보존과 후처리 타임라인도 시험했다. 해당 버전 시험은 128개 통과, 권한 opt-in 시험 1개 제외였다.

이는 실제 인물이 나오는 5분 영상의 SAM 2/SAM3D GPU 처리 시간·최대 메모리를 측정한 결과는 아니다. 실제 최대 길이의 GPU 부하 측정은 별도 확인 사항이다.

### 2.2. 첫 프레임에 사람이 없으면 추출할 수 없음

**확인된 원인**

세 부분이 모두 첫 프레임을 전제로 구현돼 있었다.

1. 초기 대상 선택은 0프레임의 검출 박스만 검사했다.
2. SAM 2 대상 seed와 추적 시작이 0프레임에 고정돼 있었다.
3. 움직임 검사도 최초 관측이 0프레임이 아니면 재선택이 필요한 상태로 처리했다.

**해결 방법 — v0.5.24**

- 자동 선택에서는 0부터 프레임 순서대로 검사해 처음 인물이 검출되는 위치를 찾는다.
- 재생바를 원하는 위치로 옮긴 뒤 **대상 확인**을 누르면 그 프레임에서 인물 번호를 선택할 수 있다.
- 대상 확인에 사용한 프레임 번호를 실제 추출 설정, SAM 2 seed, 추적 시작, 움직임 검사까지 전달한다.
- 선택 프레임에 후보가 없으면 사용자에게 알린다. 뒤의 다른 사람을 임의로 대신 선택하지 않는다.
- 후보가 여럿이면 번호 선택을 요청한다.
- 시작 전 구간은 `uninitialized / before_target_start`로 남기고 ROI·관절·예측을 생성하지 않는다.
- 원본 전체 길이, 프레임 번호와 timestamp를 유지한다. 앞부분을 잘라내거나 관절을 역으로 채우지 않는다.
- 시작 전 대기와 시작 후 추적 분실을 미리보기·경고에서 구분한다.

**예시**

```text
프레임 0~9  : 인물 없음 → 빈 상태로 보존
프레임 10   : 최초 인물 검출·선택 → 이 위치에서 추적 시작
프레임 11~  : 선택 대상을 기존 추적·추론 방식으로 처리
```

**검증과 사용자 확인**

실제 YOLOX 검출기가 앞의 10프레임이 비어 있는 테스트 영상에서 10프레임의 인물을 찾았다. GUI의 자동 탐색, 지정 프레임 선택, 추출 설정 연결과 새 영상 로드 시 초기화를 검사했다.

실제 SAM 2/SAM3D worker 본문을 CPU 모델 대역으로 실행해 전체 20프레임 유지, 앞 10프레임의 빈 관절, 뒤 10프레임만 추론 호출, 장면 전환과 초기 seed 처리도 확인했다. 해당 버전 관련 시험은 116개 통과, 권한 opt-in 시험 1개 제외였다.

2026-10-21 사용자가 적용 후 정상 동작을 확인했다. 자동 시험에서 실제 GPU 모델 추론을 실행한 것은 아니며, 사용자 확인을 모든 영상의 정확도 검증이나 정량 GPU 벤치마크로 확대하지 않는다.

이 기능은 현재 기본 **SAM3D + SAM 2 마스크** 모드에 적용했다. 옛 2D/MediaPipe/다른 추적 경로의 프레임 선택 규칙까지 모두 변경한 것은 아니다.

## 3. 추적·자세 관련 주요 보완 사항

| 문제 | 적용한 대응 | 현재 판단 |
|---|---|---|
| 다른 인물·거울로 대상이 바뀜 | 사람 추적과 자세 추정을 분리하고, 현재 기본 모드에서는 SAM 2의 선택 대상 마스크를 SAM3D ROI로 전달 | 사용자가 일반 영상에서 개선을 확인. 마스크가 유지됐다는 사실만으로 동일 인물임을 보장하지 않음 |
| 회전·웅크림·빠른 동작에서 끊김 | 마스크의 중심 움직임 예측·위치 검사, 보수적인 ROI, 재관측 확인과 장기 분실 보호 적용 | 유효한 관측이 없는 구간에 예상 박스를 실제 관측처럼 전달하지 않음. 완전 복원 보장은 아님 |
| 팔·다리 관절이 튀거나 잘못 연결됨 | 전신 후보 비교, 몸통 기준 전달, 관절별 검사, 필요한 부위 재추정, 재관측 연결 | 일반 영상의 사용 가능 범위는 개선됐으나 모든 후보가 같은 옷 위치에 틀리는 경우는 남음 |
| 화면 밖으로 발이 잘림 | 일부 보간·명시적 추정과 기존 발/다리 보완 경로 마련 | 사용자 개선 확인 이력 있음. 보이지 않는 발의 실제 관측을 얻은 것은 아님. 기존 완료된 발/다리 결과 재사용과 현재 기본 자동 경로를 구분 |
| 수동 무릎·관절 앵커가 효과 없거나 더 튐 | 수동 조작 중심의 기본 UI를 정리하고 자동 검사·부위 재추정 흐름으로 전환 | 현재 기본 추출에서 수동 앵커 조작을 요구하지 않음 |

현재의 짧은 예측·보간은 관측과 구분한다. 장기 분실이나 대상이 모호한 상태를 임의의 사람에 연결하거나, 부드러워진 결과를 정확한 관절로 확정하지 않는다.

## 4. GPU 처리 속도 저하: 확인한 원인과 조치

당시 GUI의 SAM3D 추출과 별도 일괄 추출이 동시에 실행되는 것을 프로세스 관계로 확인했다. RTX 4060 8GB에서 GPU 사용률 100%, 전용 메모리 약 7.5/8GB 상태였고, 열 제한은 감지되지 않았다.

사용자 요청에 따라 **일괄 추출 프로세스 트리만 종료**하고 GUI 추출과 기존 결과는 보존했다. 일괄 추출은 자동 재개하지 않는다.

추가로 현재 자동 보정은 원시 추론 외에 매 프레임 3개의 전신 후보와 필요한 팔다리 재추정을 요청한다. 당시 LongSword 445프레임에는 원시 445회 + 추가 후보 1,335회 + 부위 재추정 302회, 총 2,082회가 요청됐다. 이는 완료된 모든 추론 횟수나 정확도 수치가 아니다. 부위 재추정 도중 일괄 작업을 중지했다.

v0.5.16과 속도 진단 당시 v0.5.22의 기본 추론·자동 처리 코드는 동일했다. 따라서 당시 급격한 저하를 최근 실험 기능의 자동 추가 탓으로 확정하지 않았다. 단독 실행에서의 속도 회복, 버전별 동일 영상 비교, 공유 메모리 paging 여부는 정량 검증하지 않았다.

## 5. Norma의 펄럭이는 의상 문제: 보류한 이유

**현재 미해결 문제**

회전 중 망토가 다리와 겹치면 모델이 다리 대신 의상 위치에 관절을 추정한다. 단순 떨림이나 짧은 누락과 달리, 잘못된 자세가 유효한 출력처럼 생성되는 문제다.

**비교한 접근**

| 접근 | 확인한 결과·한계 |
|---|---|
| 여러 전신 후보와 부위 재추정 | 일부 프레임은 개선되지만 심한 가림에서 후보 전체가 잘못될 수 있음 |
| 사람 마스크 내부의 망토·머리카락 영역 진단 | 작업자 seed로 만든 별도 비교용 마스크이며, 자동 의상 의미 인식의 완성은 아님 |
| 의상 겹침에 따른 후보 감점 | 일부 선택은 달라졌으나 핵심 다리 오류는 남음 |
| 앞뒤 프레임 기반 자세 가설·보간 | 긴 가림과 불확실한 몸통 기준에서는 믿을 만한 양끝 자세가 부족함 |
| SAM3D에 직접 사람/의상 축소 마스크 입력 | 출력은 바뀌지만 핵심 구간 개선은 확정하지 못함 |
| 독립 RTMPose → MotionBERT 비교 | 독립 2D 관측도 옷에 붙는 경우가 있어 시간 추론만으로 실제 관절을 보장하지 못함 |
| 검사 통과 2D 관절의 native point prompt | 가이드 정합 조건은 일부 통과했지만 핵심 2초대 다리에는 통과 관측이 부족함 |

이 실험들은 별도 비교 결과로 보존했다. 최근 마스크·MotionBERT·point prompt 실험 전체가 기본 자동 추출에 적용된 것은 아니다.

**사용자와 정한 처리 방향**

Norma 같은 펄럭이는 의상의 심한 가림은 현재의 알려진 한계로 보류한다. 해결됐다고 처리하지 않으며 회귀 검증용 영상으로 남긴다. 일반 영상의 사용 가능한 결과를 기준으로 다음 단계 준비를 진행한다. Norma만을 해결하기 위한 반복 보정 실험은 지금 추가하지 않는다.

## 6. 다음 단계로 넘길 때 유지할 기준

다음 구현 대상은 계획서의 **M3 Motion Skeleton 변환**이다. 본 회전 생성은 이후 M4와 연결한다. 이번 문서 작업에서 다음 단계 구현을 시작하거나 전체 M2 정확도 통과를 선언하지는 않았다.

1. 잘 나온 일반 영상 결과로 관절 대응, 좌표축·단위, 계층과 기준 자세를 확인한다.
2. 원시 모델 데이터와 보정된 관절 데이터의 출처를 구분해 변환 입력을 정한다.
3. 빈 프레임과 미해결 관절을 0좌표나 정상 관측으로 바꾸지 않는다.
4. 카메라 상대 위치를 Unreal 월드 위치·Root Motion으로 오해하지 않는다.
5. 본 회전 단계에서는 Quaternion, 부호 연속성과 SLERP를 계획대로 검증한다. 현재 구현 완료 기능으로 표시하지 않는다.
6. 보류한 의상 가림은 추후 본 편집·키프레임 수정 또는 별도 관측/모델 연구로 다룬다. 스켈레톤 변환 자체가 잘못 추정된 관절을 자동으로 고쳐주지는 않는다.

## 7. 사용 및 복구 위치

**기본 사용**

프로그램 재실행 → MP4 입력 → 필요하면 인물이 보이는 위치로 재생바 이동 → 대상 확인 → 번호 선택 → 출력 → 결과 패널에서 비교.

0프레임에서 대상 확인을 누르거나 확인 없이 자동 출력하면 최초 후보를 탐색한다. 뒤의 특정 프레임에서 대상 확인을 누르면 그 프레임을 검사한다. 특정 위치가 비어 있으면 다른 위치에서 다시 확인한다.

**기준 파일**

- 기존 코드 MVP: [v0.5.24 ZIP](../snapshots/v0.5.24%20MVP/m2-delayed-target-start-v0.5.24.zip)
- 스냅샷 파일 수·SHA256 등: [snapshot.json](../snapshots/v0.5.24%20MVP/snapshot.json)
- 현 작업 상태: [CURRENT_TASK.md](../md/CURRENT_TASK.md)
- 누적 작업 내역: [PROGRESS.md](../md/PROGRESS.md)
- 오류 원인·조치 기록: [ISSUES.md](../md/ISSUES.md)
- 현재 구현·계획: [PROJECT.md](../md/PROJECT.md)
- 늦은 등장 검증: [verification.json](../validation/late-v0524/verification.json)
- 긴 영상 검증: [verification.json](../validation/long-v0523/verification.json)
- GPU 동시 실행 진단: [performance-diagnosis.json](../validation/all-mp4-v0522/performance-diagnosis.json)

이 요약은 기존 v0.5.24 ZIP을 만든 뒤 추가한 문서다. 기존 ZIP을 덮어쓰지 않았으며, 이 문서가 해당 ZIP 내부에도 들어 있다고 가정하지 않는다. 코드 복구 기준은 기존 ZIP, 최신 사용자 확인과 인계 내용은 이 요약 및 원본 MD를 함께 참고한다.
