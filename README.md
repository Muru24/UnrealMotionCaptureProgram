# Video to Unreal Animation Tool

현재 구현 범위는 M0 영상 입력 검증, M1 2D 추정, M2 3D 관절 출력·프리뷰 초기 구현입니다.
현재 작업 버전은 v0.5.24입니다. SAM 2 마스크 기반 대상 추적을 비교용 시험 모드로 추가했으며 M2 관절 품질 검증은 진행 중입니다.
Python 3.11과 OpenCV contrib를 사용합니다. M1은 RTMPose/YOLOX, M2는 MediaPipe Full v1과 선택형 SAM 3D Body GPU 시험 모드를 제공합니다.
설치와 모델 준비 후에는 인터넷 연결 없이 실행합니다.

## 프로토타입 창 실행

프로젝트 폴더의 **StartPrototype.cmd를 더블클릭**합니다. PowerShell 명령을 입력할 필요가 없습니다.
현재 프로젝트의 `.venv`를 사용하는 실행 파일이며, 별도 PC용 설치형 EXE는 아닙니다.

1. MP4를 드래그하거나 **영상 선택**으로 엽니다.
2. 기본 SAM 3D + SAM 2 마스크 모드에서 필요하면 **대상 확인**으로 인물을 선택합니다. 시작에 사람이 없으면 첫 검출 프레임을 찾습니다. 원하는 위치로 재생바를 옮겨 대상 확인을 누르면 그 프레임에서 번호를 선택할 수 있습니다. 등장 전 구간은 빈 상태로 보존합니다.
3. **출력**을 누르면 추출 → 후보 선택 → 다리 재추정이 자동 실행됩니다. 진행 중 취소할 수 있습니다.
4. 완료 후 다리 재추정 비교가 열립니다. 미리보기 목록으로 원시/후보/원본도 확인합니다.
5. 기존 결과는 **SAM 결과 열기**로 엽니다. 완료된 단계는 재사용하고 빠진 단계만 자동 실행합니다.

수동 관절·무릎 지정, 고정 시험 재생, 단계별 실행 버튼은 제거했습니다. 원시 결과와 기존 출력은 보존합니다. 자동 후처리 실패시 완료된 기본/후보 결과를 표시하며 상태에 사유를 남깁니다. MediaPipe/2D 비교 모드는 별도로 유지합니다.
**결과 폴더 열기**에서 JSON·리포트·MP4를 확인합니다. 아래 과거 버전 기록의 수동 버튼 안내는 현재 GUI에 적용되지 않습니다.

현재 프로토타입은 5분(300초)/18,000프레임 이하, 각 변 최대 1920px의 짝수 해상도 MP4를 지원합니다.
앱 종료 시 처리 중 작업은 취소 요청 후 모델 자원을 정리하고 종료합니다.
실행 오류·예외 로그는 로컬 `outputs/prototype.log`에 기록합니다.

GUI는 M1/M2를 실행하는 임시 작업 창입니다. v0.3.2의 추적 개선이 적용되며 관절 오추정·누락과 떨림은 아직 보정 전입니다. 기존 창을 닫고 다시 실행해야 새 코드를 사용합니다.
본 편집·프레임 보간·Unreal 출력 등 M9 전체 기능이 완료된 것은 아닙니다.
드래그 앤 드롭은 MIT 라이선스 `tkinterdnd2==0.6.4`를 사용하고 동영상 재생은 기존 OpenCV/Pillow를 재사용합니다.

## M2 3D 관절 추정과 프리뷰

인물이 한 명뿐인 `vivian.mp4` 기준 실행 예시입니다. 출력 폴더는 새 이름이어야 합니다.

```powershell
.\.venv\Scripts\python.exe -m app.cli "C:\Users\user1\Videos\vivian.mp4" --pose3d --max-people 1 --list-targets --preview-output "outputs\vivian_m2_candidates.png"
.\.venv\Scripts\python.exe -m app.cli "C:\Users\user1\Videos\vivian.mp4" --pose3d --max-people 1 --target-index 0 --output "outputs\vivian_m2_user01"
```

`--max-people 1`은 입력에 오직 한 명이 있다는 명시적 설정입니다.
여러 인물이나 거울 반사가 있으면 이 옵션을 빼거나 `--max-people 4`로 후보를 확인하세요.
M2 후보 번호는 `--pose3d --list-targets` 기준이며 M1 번호와 같다고 가정하지 않습니다.
선택 옵션을 생략하면 단일 후보일 때만 자동 초기화합니다. 다중 후보이면 지정이 필요합니다.
기존 `--target-box X1 Y1 X2 Y2`도 M2 후보의 원본 픽셀 박스를 지정하는 방식으로 사용할 수 있습니다.

- `preview3d.mp4`: 왼쪽 원본 관절 오버레이, 오른쪽 native X/Y와 Z/Y 투영. 고정 140 px/m로 표시하며 관절 변화에 따라 매 프레임 확대·축소하지 않습니다.
- `overlay.mp4`: 원본 크기의 MediaPipe 33관절 오버레이. valid 관절만 표시하며 원본 오디오는 없습니다.
- `pose3d.json`: 33개 원시 3D 관절, 원본 영상 픽셀 위치, visibility/presence, valid/reason. 결측·비유한 값은 null로 표현합니다.
- `pose2d.json`: 명시적 COCO17 대응 결과. 점수는 min(visibility,presence)로 RTMPose confidence와 의미가 다릅니다.
- `tracking.json`: 33관절 상태와 대상 유지·분실·재선택 진단.
- `report.json`: 처리 상태, 대상/유효 torso 프레임 수, 관절 상태 집계, 경고와 한계.

3D는 엉덩이 중점을 원점으로 한 추정 미터 좌표이며 전역 Root Motion이 아닙니다.
Motion Skeleton/UE 좌표로 변환한 결과가 아니고, smoothing·보간·본 편집은 아직 수행하지 않습니다.
visibility/presence 또는 유효 관절 비율을 실제 관절 정확도로 해석하지 마세요.
Ctrl+C 취소와 실패 시 저장된 JSON/리포트에 부분 결과 상태를 기록합니다.

## 캡처 대상 지정

첫 프레임에서 검출된 인물 후보를 확인합니다. 번호는 검출 박스의 왼쪽 x 좌표 순으로 0부터 시작하며, 왼쪽 좌표가 같으면 위쪽 y 좌표 순입니다.

```powershell
.\.venv\Scripts\python.exe -m app.cli "C:\Users\user1\Videos\LongSword.mp4" --list-targets
.\.venv\Scripts\python.exe -m app.cli "C:\Users\user1\Videos\LongSword.mp4" --list-targets --preview-output "outputs\target_candidates.png"
.\.venv\Scripts\python.exe -m app.cli "C:\Users\user1\Videos\LongSword.mp4" --pose2d --target-index 0 --output "outputs\LongSword_tracking_test01"
```

`--preview-output`은 후보 번호와 박스를 표시한 첫 프레임을 PNG/JPG로 저장합니다.
거울 속 인물과 실제 캡처 대상을 이미지에서 확인한 뒤 번호를 선택하세요. 기존 이미지 파일은 덮어쓰지 않습니다.
이는 클릭·드래그 선택 UI가 아니라 후보 확인용 정지 이미지입니다.

후보 번호 대신 첫 프레임의 인물 전체를 감싸는 박스를 지정할 수도 있습니다.
좌표는 `x1 y1 x2 y2` 픽셀 단위입니다. 예시 좌표는 LongSword 첫 프레임 기준이며 다른 영상에 그대로 적용하지 마세요.

```powershell
.\.venv\Scripts\python.exe -m app.cli "C:\Users\user1\Videos\LongSword.mp4" --pose2d --target-box 150 510 470 1275 --output "outputs\LongSword_box_test01"
```

선택 옵션을 생략하면 처음으로 검출된 인물이 정확히 한 명일 때만 자동 초기화합니다.
초기 인물이 여러 명이면 선택을 요청하는 오류를 출력합니다. 명시적 후보·박스는 첫 프레임에 적용하므로 첫 프레임에 사람이 없으면 사용할 수 없습니다.

초기화 후에는 이전 위치·이동·크기와 중앙 몸통의 색상 히스토그램으로 같은 대상을 보수적으로 연결합니다.
동일 인물의 큰 박스와 작은 박스가 중복 검출되는 경우에는 높은 IoU와 거의 완전한 포함 관계를 확인해 중복 후보를 억제합니다.
부분적으로 겹치는 박스는 유지합니다. 이는 박스 기반 휴리스틱이며 실제 사람 둘이 거의 포개진 경우를 완전히 구분하지는 못합니다.
다른 인물이 더 크게 검출돼도 최대 박스를 다시 선택하지 않습니다. 새 모델이나 Re-ID 모델은 사용하지 않습니다.

- tracked: 선택 대상과 연결되어 관절 추론을 수행한 프레임.
- uncertain: 검출 누락·연결 실패 등으로 자세 출력을 보류한 프레임.
- lost: 연속 5프레임을 넘게 연결하지 못한 상태. 자동으로 다른 사람을 선택하지 않습니다.
- uninitialized: 아직 자동 초기화할 인물이 검출되지 않은 상태.

짧은 검출 누락은 위치·색상 등 재연결 조건이 맞을 때만 복귀합니다. 관찰된 인물 겹침이나 후보 모호성이 발생하면 재선택 필요 상태를 유지합니다.
겹침·모호성 또는 lost 이후의 대상을 자동으로 재식별하지 않습니다. 현재 CLI는 중간 프레임 재선택 UI를 제공하지 않으며, 클릭·드래그와 분실 구간 재선택 UI는 M9에 구현할 계획입니다.
출력된 대상 프레임 비율이 50% 미만이면 사용 가능한 자세가 부족하다는 별도 경고를 출력합니다. 완료 메시지는 파일 처리가 끝났다는 의미이며 자세 품질을 보증하지 않습니다.

## 누락 원인 확인

tracking.json의 joint_states는 joint_names와 같은 순서입니다.

- valid: 화면 안에 있고 confidence 기준을 만족한 관절.
- low_confidence: 원시 관절 점수가 기준 미만.
- out_of_frame: 관절 좌표가 화면 밖에 있음.
- nonfinite: 좌표나 점수가 비정상 수치.
- target_unavailable: 추적 대상을 확정하지 못해 해당 프레임의 관절 추론을 수행하지 않음.

이 상태는 관측·추정 실패의 분류입니다. low_confidence가 실제 가림을 증명하는 것은 아닙니다.
report.json의 frames_with_detections와 frames_with_target을 비교하면 다른 사람은 검출되었으나 선택 대상은 연결되지 않은 경우를 구분할 수 있습니다.
tracking_state_counts, joint_state_counts, joint_issue_frame_counts도 함께 기록합니다.

## M1 제한

- 한 번에 지정한 1명의 전신 동작을 추정합니다. 관찰된 겹침·모호성에서는 임의 연결보다 출력 중단을 우선하므로 누락 구간이 늘 수 있습니다.
- 위치와 색상 기반의 제한된 추적입니다. 비슷한 의상, 갑작스러운 장면 전환, 프레임 사이에 완전히 가려진 교차, 큰 외형 변화에서는 동일 인물 유지가 보장되지 않습니다. 실제 다중 인물 촬영 영상의 추가 검증이 필요합니다.
- 미검출 프레임은 빈 결과로 저장합니다. confidence 0.3 미만이거나 화면 밖인 관절은 valid=false로 기록하며 보간하지 않습니다.
- 좌표는 원본 프레임의 픽셀 단위입니다. x는 오른쪽, y는 아래쪽으로 증가합니다.
- 타임스탬프는 프레임 인덱스 / 명목 FPS로 계산합니다. 가변 FPS의 원본 PTS 보존·리샘플링은 후속 작업입니다.
- 메타데이터 프레임 수와 실제 디코딩 수가 다르면 경고를 남깁니다. EOF만으로 정상 종료와 디코딩 오류를 완전히 구분할 수 없습니다.
- 최대 5분(300초) / 18,000프레임, 한 변 최대 1920픽셀, 가로·세로 짝수 해상도를 지원합니다.
- 모델은 로컬 파일과 SHA256을 검사한 후 CPU에서 실행합니다. 모델 누락 시 자동 다운로드하지 않고 오류를 안내합니다.
- 3D 복원, Motion Skeleton, smoothing, Root, Foot Lock, GUI와 Unreal 연동은 아직 구현하지 않았습니다.
- 현재 고정 CPU 모델 하나를 사용합니다. Fast / Balanced / Quality 선택은 후속 작업입니다.

### v0.3.4 관절 수동 지정과 짧은 2D 예측

프로그램을 닫고 `StartPrototype.cmd`로 다시 실행하세요. 영상을 넣고 **관절 지정**을 누르면 원본 프레임에서 골반 중심 → 어깨 중심 → 좌우 손목·발목을 클릭할 수 있습니다. 좌우는 인물 기준입니다. 필요하면 팔꿈치·무릎도 지정하세요. 슬라이더/이전·다음 프레임으로 오류가 생긴 중간 프레임을 골라 다시 지정할 수 있습니다. 적용 후 닫기 → 출력으로 전체 영상을 다시 계산합니다. 첫 프레임에 몸통 축을 지정하면 동일 축 근처의 유일한 실제 후보를 선택합니다. 중간 몸통 재지정은 명시적 대상 재선택이며, 후보가 모호하면 자동 선택하지 않습니다.

몸통 축의 상대 좌표, 이동 잔차, 연결 길이와 모델 신뢰도를 조합해 의심 관절을 검사합니다. 의심값은 기준을 갱신하지 않고, 짧은 누락은 마지막 채택 관측의 속도로 **최대0.2초** 예측합니다. 재검출은 연속2회 일치 후 연결합니다. 몸통 자체를 잃으면 예측을 중단하며, 긴 가림이나 머리카락의 그럴듯한 오추정까지 자동 복구하는 기능은 아닙니다.

지정 창의 저장/불러오기로 JSON을 보관할 수 있습니다. 원본 영상 SHA256이 맞는 파일만 불러옵니다. 새 영상을 넣으면 현재 지정은 초기화됩니다. 한쪽 몸통 점만 지정한 상태로는 적용할 수 없으며, 가린 관절의 실제 위치를 추측해 찍지 마세요.

보정 출력 `guidance2d.json`은 manual/observed/predicted/reacquired/uncertain 상태를 구분합니다. overlay에서 수동점은 분홍, 예측점은 주황, 관측점은 초록, 몸통 축은 청록입니다. 몸통 중심에서 관절로 잇는 회색 선은 보정 가이드이며 실제 쇄골·위팔 본이 아닙니다. 원시 `pose3d.json`/`pose2d.json`은 수정하지 않으며 **3D 깊이와 3D 미리보기의 world 뼈대는 아직 보정하지 않습니다.**

수동 지정이 없는 출력은 기존 경로를 사용합니다. 보고서의 guidance2d_state_counts는 관절 상태 개수이며 정확도 점수가 아닙니다. unused_anchor_frames/unapplied_anchor_frames가 있으면 디코딩되지 않은 프레임 또는 몸통 검출 부족으로 지정이 적용되지 않은 것입니다. M2 최종 통과는 계속 보류합니다.

### v0.3.5 관절 지정 악화 수정 — 검증 중

### v0.4.0 — 복합 추적 점수

프로그램 재시작 후 SAM 모드에서 사용합니다. IoU25% + 이전속도 기반 예측중심25% + 신뢰되는2D관절30% + 외형20%로 후보를 비교합니다. 거리 자체가 아닌 가까울수록 높은 유사도를 사용하며, 관절이 부족하면 나머지 가중치를 재정규화합니다. 후보별 점수는 sam-tracking.json의 association_scores에 저장합니다.

2D관절은 기존RTMPose 추적보조이고 최종3D는SAM입니다. 외형은현재HSV색상특징이며 학습된Appearance/ReIDembedding은 아직 없습니다. 속도/외형/관절이 충분하면IoU0인 빠른이동도 연결하지만 같은옷/회전/가림의 정확한신원보장은 아닙니다.

4개실제영상의 추적프레임수는 v0.3.9와 동일합니다. 특히Norma65에서는 두후보 모두 신뢰관절이 거의없어 관절점수를 쓸수없고 모호성으로 정지합니다. 가중치추가만으로개선되었다고판정하지않습니다. 장기분실프레임의SAM/발보완금지는유지합니다. Windows취소는실제Python자식까지정리하도록보완했습니다. GPU를쓰는다른추출이동시에실행되면속도가크게느려질수있습니다.


### v0.4.8 — 관절 위치 검토 표시

SAM의 **3D 누락 보완** 결과에 본 길이 이상·짧은 방향 튐 검토를 추가했다. 자홍색은 검토 후보이고 주황색은 기존 보간/추정이다. **다음 검토** 버튼으로 해당 프레임에 이동한다. 보고서와 pose-quality.json에 구간/본/사유를 기록하며 관절값은 이 검사로 바꾸지 않는다. 빠른 실제 동작도 표시될 수 있고, 일정하게 잘못 잡힌 머리카락·의류 관절은 검출되지 않을 수 있다.

### v0.5.0 — SAM 2 마스크 추적 시험 모드

출력 유형에서 **SAM 3D + SAM 2 마스크 (시험)**을 선택하고, 대상 확인으로 첫 프레임 인물을 지정한 뒤 출력합니다. 기존 SAM 3D Body 모드는 v0.4.10 추적을 유지합니다. 새 모드는 첫 프레임 YOLOX 박스로 초기화한 이후 SAM 2.1 Small 영상 메모리로 마스크를 추적합니다. 프레임 연결에 2D 관절을 사용하지 않습니다. 마스크 외접박스에 여유를 더해 SAM3D에 원본 ROI를 전달하며 마스크 밖을 검게 지우지 않습니다.
